# なぜ Hermes なのか

Hermes は、あなたのサーバー上で動作する永続的・自律的な AI エージェントです。セッションをまたいで蓄積される階層化メモリ、あなたがオフラインの間もジョブを実行する cron スケジューラ、再利用可能な手順を自動的に保存する自己改善型のスキルシステムを備えています。ターミナル、ブラウザ、メッセージングアプリのいずれからでも到達でき、しかもそれは毎回「同じ履歴を持つ同じエージェント」です。

このドキュメントでは、Hermes のメンタルモデル、他ツールとの誠実な比較、そして Hermes が適している場面・適していない場面を説明します。

---

## 本質的な課題: 多くのツールは「その瞬間」は優秀だが「時間軸」では弱い

メモリ機能はもはやそれ単体では差別化要因になりません。ChatGPT、Claude、Cursor、GitHub Copilot はいずれも何らかのメモリを備えています。Anthropic、OpenAI、Microsoft はいずれもスケジューリングやエージェント機能を投入中です。12か月前に存在したカテゴリの境界は、急速に曖昧になっています。

Hermes はメモリや自動化を持つ唯一のツールではありません。Hermes が特異なのは、それらの能力を **永続的・セルフホスト・サーフェス横断・累積的** にし、しかも自分のサーバー上で実現する点です。本当に重要な区別は「メモリがある/ない」ではなく、次の点にあります。コンテキストがセッションをまたいで自動的に永続するか、実行が自分の管理するハードウェア上で行われるか、どのデバイスからでも同一のエージェント・アイデンティティに到達できるか、そして手動設定なしにあなた固有のワークフローに対してシステムが時間とともに有意に上達するか。

```
セッションスコープ:   あなた -> [ツール] -> 回答 -> 終了
                      （メモリを持つツールもあるが、実行自体はステートレス）

永続エージェント:     あなた <-> [Hermes] <-> （メモリ・スキル・スケジュール・ツール・サーフェス）
                      （自分のサーバー上で動作し、コンテキストを蓄積し、オフラインでも代行する）
```

## 収束（コンバージェンス）についての注記

市場は収束しつつあります。チャットアシスタントはタスクスケジューリングやファイルコネクタを追加し、IDE ツールはクラウドエージェントモードを投入し、CLI ツールはスキルシステムやモバイルサーフェスを追加しています。「アシスタント」「エディタ」「エージェント」の境界は溶けつつあります。

これは比較を難しくする一方で、問いをより鋭くします。すなわち、どのツールも「あらゆる機能の何らかの版」を謳う時代に、実際に重要なのは何か、という問いです。Hermes にとっての答えは **統合（synthesis）** です。メモリ、スケジューリング、メッセージングといった単一機能はどこか他にも存在します。価値は、それらすべてを **一つのセルフホストなシステム** にまとめ、継続的に動作させ、あなたのスタックに関する実知識を時間とともに蓄積する永続的アイデンティティを持つことにあります。

## 3つの柱

### 1. 複利的に積み上がるメモリ

Hermes は、あらゆるセッション・再起動・モデル切り替えを生き延びる階層化メモリを持ちます。

- User profile — あなたが誰か、好み、コミュニケーションスタイル、Hermes に修正させた事項
- Agent memory — あなたの環境、ツールチェーン、プロジェクト規約に関する事実
- Skills — Hermes が自動的に発見・保存する再利用可能な手順。アプリのデプロイ方法、テストの実行方法、PR レビュー方法を学び直す必要が一切ない
- Session history — 過去の会話はすべて検索可能。先週の火曜に何をしていたかを Hermes は思い出せる

あなたが Hermes を修正すれば、それを覚えます。難しい問題を解決すれば、その手法を保存します。スタックを学習すれば、その知識は今後すべてのセッションに引き継がれます。これを手動で設定することはありません。通常利用の副作用としてバックグラウンドで起こります。

### 2. 自律スケジューリング

Hermes はあなたが不在でもジョブを実行できます。毎時、毎朝、任意の cron スケジュールで。新しいセッションをメモリとスキルへのフルアクセス付きで起動し、タスクを実行し、結果を好きな場所へ届けます。Telegram、Discord、Slack、Signal、WhatsApp、SMS、メールなど。

あなたが眠っている間に Hermes ができること:

- GitHub リポジトリの新しい pull request をレビューし、完全な判定コメントを投稿する
- ニュース、市場、その他追跡対象のモーニングブリーフィングを送る
- テストスイートを実行し、何か壊れたら通知する
- 競合のブログを監視し、新規投稿を要約する
- データソースを監視し、しきい値を超えたら通知する

クラウド型スケジューラとの違いは、ジョブが **あなたのサーバー上で、あなたのメモリとスキルとともに** 実行され、データがハードウェアから外に出ないことです。

### 3. どこからでも到達できる

Hermes はあなたのサーバー上で動作し、あらゆるサーフェスから到達できます。SSH 経由のターミナル、Web UI（本プロジェクト）、そして Telegram・Discord・Slack・WhatsApp・Signal・Matrix を含むメッセージングアプリです。スマホでタスクを開始し、ノート PC のブラウザで確認し、リモートサーバーのターミナルで継続する。同じエージェント・メモリ・履歴が、すべてのサーフェスにわたって付いてきます。

## 今日の AI ツールはどう階層化されているか

旧来の4カテゴリモデル（チャット、エディタ、CLI、エージェント）は綺麗すぎます。これらの層は活発に互いへ崩れ込んでいます。より誠実な見取り図は次の通りです。

チャットアシスタント（Claude.ai、ChatGPT）は、いまや永続メモリ、タスクスケジューリング、50以上のサービスコネクタ、場合によっては computer use を伴う完全なエージェントモードを備えます。もはや「ただのチャット」ではありません。

IDE ツール（Cursor、Windsurf、Copilot）は、セッション横断メモリ、クラウドベースのバックグラウンドエージェントを投入済み・投入中であり、Cursor の場合は Slack 連携を伴う完全な Automations プラットフォームを持ちます。Cursor v3.0（2026年4月）は明確にエージェントファーストです。

CLI ツール（Claude Code、Codex、OpenCode）は hooks、skills、デスクトップアプリの自動化、マルチサーフェス到達を追加してきました。Claude Code は現在ターミナル・IDE・デスクトップ・ブラウザにまたがります。Codex は CLI・IDE 拡張・デスクトップアプリ・Codex Cloud から成る製品ファミリーになりました。

永続セルフホストエージェント（Hermes、OpenClaw）はその交点に位置します。CLI エージェントのツール利用能力、チャットアシスタントのメモリ、自動化プラットフォームのスケジューリング、メッセージング連携のサーフェス横断到達を組み合わせ、自分が所有するハードウェア上で継続的に動作します。

問うべきはツールがどのカテゴリに属するかではありません。問うべきは、実際にどの能力の組み合わせが必要か、その実行がどこに置かれるか、そしてシステムがあなた固有のコンテキストに対して時間とともに上達するか、です。

## Hermes の比較

### vs. OpenClaw

OpenClaw は最も直接的な比較対象であり、多くの人が最初に尋ねる相手です。両者ともオープンソースでセルフホスト、永続メモリ・cron スケジューリング・メッセージングアプリ連携を備えた常時稼働エージェントです。Hermes を評価するなら、OpenClaw も評価してください。

OpenClaw（MIT）は Node.js/TypeScript で書かれた Gateway コントロールプレーンを中心に構築されています。この分野で最も広いメッセージングカバレッジを持ち、WhatsApp、Telegram、Signal、iMessage、LINE、WeChat、Slack、Discord、Teams、Matrix、Google Chat、Feishu、Mattermost、IRC、Nextcloud Talk など24以上のチャネルに対応します。CDP 経由のネイティブ Chrome/Chromium 制御、macOS・iOS でのボイスウェイクワード、10,700以上のスキルを擁する ClawHub マーケットプレイスを持ちます。コミュニティは大規模（GitHub スター35万以上、コミット16,900以上）で成長中です。

Hermes は Python で構築され、Gateway コントロールプレーンではなく **自己改善型のエージェントループ** を中心に据えています。核心的なアーキテクチャの違いはスキルにあります。OpenClaw のスキルは主に人間が作成し、マーケットプレイスからインストールするプラグインです。Hermes は **各セッションの一部として自分のスキルを自動的に記述・保存** します。Hermes が問題を新しいやり方で解決すると、その手順を保存し、ユーザーの手間なしに再利用します。これは些細な違いではなく、Hermes がプラグインライブラリを保守せずともあなたのワークフローに対して有意に上達する理由です。

直接知っておく価値のある実務上の違いが2点あります。

安定性。OpenClaw の GitHub issue やコミュニティフォーラムには、アップデートで壊れる回帰が繰り返し記録されています。Telegram 連携は2026年初頭から少なくとも2026年4月まで、複数のリリースにわたって壊れていました。OpenClaw が依存する非公式の WhatsApp Web プロトコルは切断され、定期的な再ペアリングを要します。これは OpenClaw 自身の FAQ に記載があります。

セキュリティ。ClawHub のオープンな公開モデルは大規模に悪用されてきました。2026年初頭の3つの独立した監査が深刻な問題を発見しています。Koi Security（2026年1月）は335個のスキルを、macOS 上で Atomic Stealer マルウェアを配布する「ClawHavoc」キャンペーンに結び付けました。Bitdefender は当時のエコシステムの約20%にあたる約900個の悪意あるパッケージを発見しました。Snyk の「ToxicSkills」レポート（2026年2月）は、スキャンした約4,000パッケージにまたがって悪意あるスキルを発見しました。中国の CNCERT は ClawHub に関する国家的警告を発しました。Hermes はサードパーティのマーケットプレイスを持たず、それに応じて攻撃対象領域も小さくなっています。

OpenClaw の真の強みは率直に述べる価値があります。より広いメッセージングカバレッジ（iMessage、LINE、WeChat、Teams、Google Chat — Hermes が非対応のプラットフォーム）、Chrome CDP 経由のネイティブブラウザ・コンピュータ制御、ボイスウェイクワード、より大きなコミュニティ、そして Hermes より多いサードパーティ連携。これらの能力が最重要なら、OpenClaw は真剣に検討する価値があります。

Hermes の方が合う場面: プラグインライブラリを管理せずに経験から自己改善するエージェントが欲しい、Python で作業し ML/データサイエンスのエコシステムを使いたい、アップデート間で壊れない安定したデプロイが欲しい、コントロールダッシュボードではなく本格的な Web チャット UI が欲しい。

| | OpenClaw | Hermes |
|---|---|---|
| 永続メモリ | あり | あり |
| スケジュールジョブ（cron） | あり | あり |
| メッセージングアプリ連携 | あり（24以上、iMessage/WeChat/LINE 含む） | あり（多数のプラットフォーム） |
| Web UI | チャット UI ＋コントロールダッシュボード | 本格的な3ペインチャット UI |
| セルフホスト | あり | あり |
| オープンソース | あり | あり |
| 自己改善型スキル | 部分的（AI が生成可能だがデフォルトのループではない） | あり（自動・第一級） |
| ブラウザ/コンピュータ制御 | あり（ネイティブ Chrome CDP） | shell/ツール経由 |
| ボイスウェイクワード | あり（macOS/iOS） | なし |
| Python / ML エコシステム | なし（Node.js） | あり |
| Claude Code / Codex のオーケストレーション | なし | あり |
| マルチプロファイル対応 | binding-rule ルーティング経由 | あり（名前付きプロファイルが第一級） |
| プロバイダー非依存 | あり | あり |
| アップデートの信頼性 | 中（回帰が記録されている） | 高 |
| メモリの可視性 | 限定的 | あり（markdown ファイル、編集可能） |
| セルフホストの自律実行 | あり | あり |

### vs. Claude Code（Anthropic）

Claude Code は Anthropic 公式のエージェント型ツールで、集中したコーディングセッションには最も強力な選択肢の一つです。深いコード理解、shell アクセス、ファイル編集、複数ステップの推論を備えます。急速に拡張しており、現在はターミナル・IDE プラグイン・デスクトップアプリ・ブラウザのサーフェスにまたがり、いくつかの領域で差が縮まっています。

知っておく価値のある Claude Code の機能:

- Hooks システム — 26種類のイベント（SessionStart、PreToolUse、PostToolUse、Stop など）と4種のハンドラ（shell コマンド、HTTP エンドポイント、LLM プロンプト、サブエージェント）。エージェントのライフサイクルを非 LLM で決定論的に制御できる
- Plugins / Skills — `/plugin install` でインストール可能、`~/.claude/skills` からホットリロード、マーケットプレイスあり。完了目標に向けた自律反復のための公式 ralph-wiggum プラグイン（`/ralph-loop`）を含む（`/loop` とは別物）
- `/loop` — プラグイン不要で全セッションで使えるネイティブ同梱スキル。アクティブな CLI セッション内で繰り返しスケジュールでプロンプトを実行する（ポーリング/監視用途）。セッションスコープで、ターミナルを閉じると消える
- スケジューリング — クラウド管理の cron（Anthropic インフラ、最短1時間間隔）とデスクトップアプリのスケジュールタスク（アプリが開いている間ローカル実行、最短1分間隔、ローカルファイルへのフルアクセス）。セルフホストの cron はない
- メッセージングチャネル — Channels 機能経由の Telegram・Discord・iMessage（research preview、Bun ランタイム必須）。Slack は最も要望が多いが未提供
- メモリ — プロジェクトレベルのコンテキスト用 CLAUDE.md と MEMORY.md。v2.1.59 以降は auto-memory あり
- Claude Cowork — Gmail、Microsoft Teams、Notion、Jira、Salesforce など38以上のサービスを MCP 経由で接続する別個のナレッジワーカー製品

Claude Code のソースは2026年3月に短時間・偶発的に公開された後、取り下げられました。CLI は Bun でコンパイルされた minify/bundle 済み TypeScript として配布されており、オープンソースではありません。

残る主な違い:

- スケジューリングはクラウド（Anthropic インフラ、データがハードウェア外、最短1時間）かデスクトップアプリ（ローカル実行だがアプリを開いたままにする必要があり、ヘッドレスなサーバープロセスではない）を要する。Hermes の cron のようにサーバーデーモンとして動くものはどちらもない
- メモリはプロジェクトファイルベース（CLAUDE.md / MEMORY.md ＋ローリングな auto-memory）。Hermes のようにプロジェクト横断の知識グラフを自動蓄積はしない
- プロバイダー非依存ではない — Anthropic、Bedrock、Vertex、Foundry を経由するが常に Claude モデル。GPT・Gemini・ローカルモデルへ切り替えられない
- メッセージングチャネルは依然 research preview で本番向けではない

Hermes は Claude Code を **サブエージェント** として使えます。大規模な実装タスクでは、Hermes が Claude Code を起動して重い処理を任せ、その結果を自身のメモリと履歴に折り込めます。

| | Claude Code | Hermes |
|---|---|---|
| 永続メモリ（自動） | 部分的（CLAUDE.md / MEMORY.md ＋ auto-memory v2.1.59+） | あり |
| Skills / hooks システム | あり（26イベントの Hooks ＋ Plugin/Skills マーケットプレイス） | あり（経験から自動生成） |
| スケジュールジョブ（セルフホスト） | なし（クラウドまたはデスクトップアプリのみ） | あり |
| メッセージング連携 | 部分的（Telegram/Discord/iMessage は preview、Slack 未提供） | あり（多数のプラットフォーム、本番） |
| Cowork コネクタ（Slack、Gmail 等） | あり（Claude Cowork 経由、別製品） | エージェントのツール利用経由 |
| Web UI | あり（claude.ai/code、Anthropic ホスト） | あり（セルフホスト） |
| プロバイダー非依存 | なし（Claude モデルのみ） | あり（任意のプロバイダー） |
| セルフホストのスケジューリング | なし | あり |
| オープンソース | なし | あり |
| バックグラウンド/クラウドエージェントモード | あり（クラウドスケジュール） | あり（セルフホスト cron） |
| Hermes のサブエージェントとして動作 | あり | 該当なし |
| メモリの可視性 | 部分的（CLAUDE.md は可読、auto-memory はより不透明） | あり（markdown ファイル） |

### vs. Codex CLI（OpenAI）

Codex CLI（Apache 2.0、GitHub スター約6万）は素朴なターミナルツールとして始まり、製品ファミリーへ拡張しました。TypeScript から Rust へ書き直されています。現在は IDE 拡張、Automations 機能を持つデスクトップアプリ、リモート実行用の Codex Cloud を含みます。Skills システムはサーフェス間で共有されます。12以上の組み込みプロバイダー（OpenAI、Anthropic、Google/Gemini、Mistral、Groq、Ollama、OpenRouter、LM Studio、Together AI、DeepSeek、xAI、Azure OpenAI、カスタムエンドポイント）に対応します。

CLI 自体にはネイティブなスケジューリングがありません（feature request がオープン）。セッション継続は `codex resume` で可能です。メモリはセッション履歴ベース＋ AGENTS.md のプロジェクトコンテキストで、全プロジェクトをまたいで蓄積する生きた知識グラフではありません。ファーストパーティのメッセージング連携はありません。デスクトップアプリの Automations 機能はスケジュールされたローカルタスクを扱いますが、Hermes が持つセッション横断・サーフェス横断の継続性には届きません。

| | Codex CLI | Hermes |
|---|---|---|
| 永続メモリ | 部分的（セッション履歴 ＋ AGENTS.md） | あり（自動・階層化） |
| スケジュールジョブ | 部分的（デスクトップアプリの Automations。CLI にはなし） | あり |
| メッセージングアプリ連携 | なし | あり |
| Web UI | なし（CLI ＋デスクトップアプリ） | あり（セルフホスト） |
| プロバイダー非依存 | あり（12以上） | あり |
| セルフホスト | あり | あり |
| オープンソース | あり（Apache 2.0） | あり |
| バックグラウンド/クラウドエージェントモード | あり（Codex Cloud） | あり（セルフホスト cron） |
| 自己改善型スキル | なし | あり |

### vs. OpenCode

OpenCode は75以上のプロバイダーに対応するオープンソースの TUI 型エージェントコーディングアシスタントです。バイナリに組み込まれた WebUI、公式デスクトップアプリ、SQLite のセッション履歴、AGENTS.md のプロジェクトコンテキストを持ちます。Claude Code から移行するユーザー向けに CLAUDE.md をフォールバックとして対応します。30以上のコミュニティプラグインがあり、Telegram・Slack・Discord・Microsoft Teams 向けのコミュニティ製メッセージング連携が存在しますが、いずれもファーストパーティではなく手動設定が必要です。

OpenCode Go（月10ドル）と OpenCode Zen（厳選モデルサービス）はサブスクリプション層です。GitHub Copilot 公式連携は2026年1月に開始しました。ネイティブなスケジューリングはなく、コミュニティ製のバックグラウンドプラグインが存在します。自動のセッション横断セマンティックメモリはありません。

| | OpenCode | Hermes |
|---|---|---|
| 永続メモリ | 部分的（セッション履歴 ＋ AGENTS.md） | あり（自動・階層化） |

### vs. Cursor

Cursor は大きく変化しました。「メモリなし、スケジューリングなし、メッセージングなし」という説明は2024年には正確でしたが、いまや誤りです。

Memories（プロジェクト単位のセッション横断ナレッジベース）は2025年6月の v1.0 でベータ提供されました。Automations は2026年3月5日に開始 — 時間ベース、イベントベース（GitHub/Linear/PagerDuty）、コミュニケーションベース（Slack）のトリガーがクラウド VM 上のバックグラウンドエージェントを起動します。Web アプリ、モバイルエージェント、Slack ボットがマルチサーフェス到達を与えます。Cursor v3.0（2026年4月2日）は Design Mode と30以上のマーケットプレイスプラグインを備え、明確にエージェントファーストです。Cursor はオートコンプリート用に Supermaven を買収しました。2026年初頭時点で評価額293億ドル、ARR 20億ドルです。もはや狭いエディタツールではありません。

Hermes は依然として異なるプロファイルを持ちます。セルフホストでサーバー常駐であり、同一の永続アイデンティティがクラウド仲介なしにあらゆるサーフェスへ付いてきて、クラウド VM ベースではなく任意のモデルファミリーで動作します。データ主権、セルフホストのスケジューリング、または自分のハードウェア上での深い Python/ML ツールを要するワークフローにとって、Cursor のクラウドエージェントアーキテクチャは根本的なミスマッチです。一方、強力な IDE 統合を伴うエディタネイティブなエージェントが欲しいチームにとって、Cursor の近年の進化は重要です。

### vs. Claude.ai と ChatGPT

これらはもはや単純なチャットツールではありません。「メモリなし、スケジューリングなし、メッセージングなし」という説明はどちらにも不正確です。

Claude Cowork（Claude Desktop 内）は2026年2月25日にスケジュールタスクを開始 — 毎時、毎日、毎週、平日、オンデマンド。ファイルと shell アクセスを持つ隔離 VM で動作します。Claude は2026年2月時点で Slack（2026年1月26日開始）、Gmail、Google Calendar、Google Drive、Microsoft 365、Notion、Asana、Linear、Jira を含む50以上のサービスコネクタを持ちます。メモリはユーザーが手で登録した項目だけでなく、チャット履歴から自動生成されます。Artifacts でのコード実行とファイルアクセスはサンドボックス化されており、自分のサーバー上の shell アクセスとは異なります。

ChatGPT は Agent Mode（2025年7月17日開始）、Scheduled Tasks（2025年1月、繰り返し自動プロンプト）、computer-using agent、Projects、Gmail・GitHub・Google Drive を含む50以上のコネクタ、デュアルモードメモリ（自動＋手動）、そして Pro ユーザー向けの ChatGPT Pulse（毎日のリサーチブリーフィング）を持ちます。受動的な Q&A インターフェースではありません。

Claude.ai と ChatGPT が Hermes と異なる点: どちらもセルフホストではなく、プロバイダー非依存でもなく、自分のハードウェア上での実行を与えません。コネクタやスケジューリングは存在しますが、Anthropic や OpenAI のインフラ上で動きます。メモリ、セッション履歴、エージェント実行は彼らのサーバー上に存在し、あなたのものではありません。多くのユースケースではそれで問題ありません — 高機能でサポートも手厚いです。しかしプライバシーを重視するユーザー、規制環境、または管理下のハードウェア上で永続的なサーバーサイド実行を要するワークフローにとっては、失格となる制約です。

## 複利的なアドバンテージ

Hermes を上記の多くのツールと区別するのは、**手動設定なしに、あなた固有のワークフローに対して時間とともに有意に上達する** 点です。

Hermes は新しい環境に出会うたびに事実をメモリへ保存します。問題を新しいやり方で解決するたびに、その手法をスキルとして保存します。あなたが修正するたびに、あなたに関するプロファイルを更新します。あらゆるセッション、あらゆるスケジュールジョブ、あらゆるツール呼び出しが、あなた固有で、あなたのハードウェアに保存され、今後のすべての対話で利用可能な知識体系に加わっていきます。

Claude Code のセッションは1日目と100日目で同一です — 毎回まっさらから始まります。Hermes のエージェントは1日目と100日目で、あなたのスタック、規約、好み、過去に有効だった解決策を知っています。これこそが実際の複利効果です。

## Hermes は誰のためのものか

毎セッション自分のスタックを説明し直したくない、自分の環境を本当に理解した AI が欲しいソロ開発者・パワーユーザー。

共有サーバーで、各自が別々のサブスクリプションを支払ったり別々のローカルツールを動かしたりせずに高機能な AI アクセスを求める複数人のチーム。

スケジュールでタスクを実行し、結果をスマホに届け、面倒を見なくてよい AI が欲しい自動化中心のワークフロー。

会話・メモリ・ファイルを自分のハードウェア上に置きたいプライバシー重視のユーザー。

コスト・能力・レート制限に応じて OpenAI、Anthropic、Google、DeepSeek などを切り替えたい、しかも毎回ワークフローを作り直したくないマルチモデルユーザー。

## Hermes は何ではないか

Hermes は最良のエディタ内オートコンプリートツールではありません。Cursor や Windsurf の方がその仕事は得意です。Hermes と併用してください。

ゼロセットアップではありません。あなたはサーバーを動かしています。つまり初期設定が必要で、稼働時間・アップグレード・バックアップの責任を負います。トレードオフはデータ主権とコントロールであり、それを本当に望む場合にのみ意味があります。

弱いモデルを魔法のように強くはしません。メモリとスキルは助けになりますが、推論の質は依然として基盤モデルが決めます。弱いモデルを使う Hermes は「よく整理された弱いモデル」です。

高リスクな自動化には、依然としてガードレール・承認・可観測性が必要です。shell アクセスを伴うスケジュール自律実行は強力で、何を承認するかの判断を要します。ターミナルコマンドは実行前に確認を要求できます。重要なものにはそれを使ってください。

一度きりの回答やちょっとした編集への最小摩擦の経路が必要なら、チャットインターフェースやエディタ内ツールが正解です。Hermes は継続性と自律性のためのものであり、最小摩擦のワンショットのためのものではありません。

## スコープと限界

Hermes はターミナル・ブラウザ・メッセージングアプリに存在します。エディタ内オートコンプリートとインライン diff には Cursor や Windsurf を使ってください — その仕事は彼らの方が得意で、Hermes とも相性良く併用できます。

Hermes は自分のサーバー上で動かします。初期設定が必要ですが、データはハードウェアに留まり、スケジュール・モデル・コストを自分で制御できます。

Hermes はオーケストレーションとメモリのレイヤーです。どのモデルを指し示しても、時間とともにそれをより有用にします。推論はモデルが行い、Hermes はその推論が耐久性のある何かに蓄積されることを保証します。

## セキュリティとコントロール

メモリは可読・編集可能なファイルとしてサーバー上にローカル保存されます。user profile、agent memory、skills はすべて markdown です。セッション履歴は自分のマシン上の SQLite にあります。それらのいずれも直接確認・編集・削除できます。

外部メモリプロバイダーが必要なら、8種類に対応します。Mem0、Honcho、Hindsight、RetainDB、ByteRover、Supermemory、Holographic ほか。これらは任意で設定可能です。

実行は設定可能なバックエンドで動作します。ローカル shell、Docker、SSH、Daytona、Singularity、Modal。Hermes がどの実行環境で動作し、何に到達できるかを選べます。

ターミナルコマンドは実行前に確認を要求できます。本番システムに触れたり外部呼び出しを行ったりする自動化には、承認コントロールを有効化してください。

シークレットはハードウェアに留まります。Hermes は phone home せず、設定したモデル API を直接呼び出すだけです。

複数プロファイルがユーザーやプロジェクト間の隔離を与えます。共有サーバーは、別々のメモリ・別々のスキル・別々の履歴を持つ別々のプロファイルを持てます。
