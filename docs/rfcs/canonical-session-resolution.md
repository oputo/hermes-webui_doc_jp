# 正典セッション解決コントラクト

- **Status:** Proposed
- **Author:** @ai-ag2026
- **Created:** 2026-05-25
- **Tracking issue:** [#2361](https://github.com/nesquena/hermes-webui/issues/2361)
- **Related architecture:** [#1925](https://github.com/nesquena/hermes-webui/issues/1925), [`webui-run-state-consistency-contract.md`](webui-run-state-consistency-contract.md)

## Problem

WebUI は同じ会話に複数のブラウザ向けエントリポイントから到達できます:

- `/session/<session_id>` のような URL ルート、
- `?session=<session_id>` や `?session_id=<session_id>` のようなクエリパラメータ、
- ブラウザの `localStorage` のアクティブセッション値、
- `/api/sessions` から構築されるサイドバー行、
- リンク、検索、インポートされたセッション一覧からの直接セッションオープンアクション、
- 再読み込み、認証リダイレクト、PWA 再開後のブラウザブート復元。

自動圧縮の後、それらのエントリポイントは1つの論理会話系統の異なる行を指し得ます。圧縮前の親スナップショットは有効なアーカイブセッションのまま残り得る一方、ユーザー向けの会話の先端はより新しい継続に移っています。各呼び出し元が独立して ID を解決すると、UI はセッションを失ったように見えたり、古い1メッセージのスナップショットを再オープンしたり、サイドバー行を重複させたり、耐久データがまだあるのに誤ったトランスクリプトを優先したりし得ます。

このコントラクトは、それらのエントリポイントの期待される解決セマンティクスを定義します。run adapter RFC より意図的に狭く、これは実行所有権を移すのではなく、正しい可視セッションターゲットを選ぶことについてです。

## Goals

- セッションと圧縮系統の、1つの正典のブラウザ向け解決コンセプトを定義する。
- URL、クエリパラメータ、localStorage、サイドバー、直接オープンの挙動が同じメンタルモデルを使うようにする。
- 継続が存在するとき、アーカイブされた親スナップショットがデフォルトのアクティブターゲットにならないようにしつつ、それらを保持する。
- 将来のセッションルーティング、サイドバー、圧縮系統の変更に向けて、レビュアーに小さなチェックリストを与える。

## Non-goals

- アーカイブされた `pre_compression_snapshot` 行を削除しない。
- このコントラクトの一部としてセッションファイルをマージ・書き換えしない。
- state.db/セッションサイドカー調停を置き換えない。
- 狭いフロントエンドガードが着地する前に新しいバックエンドエンドポイントを要求しない。
- ユーザーがアーカイブスナップショットを記録として意図的に開くとき、明示的な履歴閲覧を変えない。

## Terms

| 用語 | 意味 |
|---|---|
| Requested session ID | ルート、クエリパラメータ、localStorage、サイドバークリック、直接セッションオープンが供給する ID。 |
| Canonical visible session | WebUI が通常のチャットナビゲーションでデフォルト表示すべきセッション行。 |
| `canonical_visible_session_id` | 正典の可視セッションを識別する API またはヘルパー出力の提案フィールド/名前。 |
| Compression snapshot | `pre_compression_snapshot` が設定された、保持されたアーカイブ親行。 |
| Continuation session | 圧縮後に作られたアクティブな子/先端。通常 `continuation_session_id`、`_lineage_tip_id`、より新しい系統メタデータで表現。 |
| Lineage relation | 1つの論理会話に属する行を繋ぐ `parent_session_id`、`_lineage_root_id`、`_lineage_tip_id`、`_compression_segment_count` などのリンク。 |

## Resolution Rules

1. **直接有効な非スナップショット ID は安定のまま。** 要求されたセッション ID が存在し `pre_compression_snapshot` でないなら、通常は自身に解決すべき。
2. **スナップショット親は可視の継続先端に譲る。** 要求されたセッション ID が `pre_compression_snapshot` で、セッション一覧に同じ系統内のより新しい非スナップショット継続があるなら、通常のチャットナビゲーションはその継続を `canonical_visible_session_id` として解決すべき。
3. **明示的なアーカイブ/履歴閲覧は依然可能。** 将来の UI 操作がスナップショットを履歴記録として意図的に開き得るが、それは通常のブート復元、URL 復元、サイドバー継続とは別個のモードであるべき。
4. **ローカルブラウザ状態はアドバイザリー。** `localStorage` は最後のアクティブ ID を覚え得るが、ブラウザブート復元はそれを要求されたセッション ID として扱い、描画前に依然正典解決を実行すべき。
5. **クエリエイリアスは同じリゾルバを共有。** `?session=...`、`?session_id=...`、`/session/...` は別個の優先ルールを持つのではなく、同じ requested-ID 経路に供給すべき。
6. **サイドバー折りたたみとセッション読み込みが一致。** 系統の可視代表として選ばれた行は、通常のナビゲーション中にその系統について `loadSession()` が開くターゲットに一致すべき。
7. **404 自己修復は系統解決と別。** 欠如/削除されたセッションは依然 stale-route 復旧経路を使うべき。ライブな継続を持つ存在するアーカイブ親は 404 ではなく、正典化の問題である。

## Entry Point Matrix

| エントリポイント | 入力 | 期待される解決 |
|---|---|---|
| URL ルート | `/session/<id>` | `<id>` を要求として扱い、通常の描画前に正典の可視セッションに解決。 |
| クエリパラメータ | `?session=<id>` または `?session_id=<id>` | URL ルートと同じ。クエリの綴りがターゲットセマンティクスを変えてはならない。 |
| localStorage | 最後のアクティブセッション ID | ブラウザブート復元中のアドバイザリーな要求 ID。描画前に正典化。 |
| サイドバークリック | 可視行 ID または系統代表 | その行が代表する同じ正典の可視セッションを開く。 |
| 直接セッションオープン | プログラム的呼び出し/検索/インポートリンク | 呼び出し元がアーカイブ閲覧に明示的にオプトインしない限り、共有の requested-ID リゾルバを使う。 |
| ブラウザブート復元 | 再読み込み/認証/PWA 再開後の URL および/または localStorage 状態 | 明示的な URL/クエリ入力を優先、次に localStorage、その後要求された ID を正典化。 |

## Review Checklist

セッションルーティング、圧縮系統、サイドバー折りたたみ、ブート復元、直接セッションオープン、URL パースに触れる PR では、次に答える:

- どのエントリポイントが要求されたセッション ID を提供するか?
- 該当する箇所でコード経路がルート形式とクエリパラメータ形式の両方を受け付けるか?
- localStorage は URL 復元と同じ正典化経路を通るか?
- 非スナップショット `continuation_session_id` / `_lineage_tip_id` が存在するとき、`pre_compression_snapshot` がデフォルトのアクティブチャットになり得るか?
- サイドバー折りたたみと `loadSession()` が同じ可視代表を選ぶか?
- 欠如セッションの 404 復旧が、存在するがアーカイブされた系統の正典化と区別されているか?
- ルート、クエリパラメータ、localStorage、サイドバーの経路が圧縮系統行で一致することを、どの回帰が証明するか?

## Rollout Plan

1. この提案コントラクトを文書化し、公開コントラクト索引からリンクする。
2. それが保つ関連ルールを参照しつつ、狭いバグ修正を小さく保つ。
3. URL/クエリ/localStorage/サイドバーの requested-ID 入力に共有フロントエンドヘルパーのカバレッジを追加。
4. バックエンドのセッション API が後で `canonical_visible_session_id` を公開するなら、古い WebUI サーバー向けのクライアントフォールバックを保ちつつ、フロントエンドリゾルバがバックエンド値を優先するようにする。
5. #1925 が実行/セッション所有権をアダプタの背後に移すなら、このコントラクトをアダプタ向けのセッションナビゲーション不変条件として引き継ぐ。
