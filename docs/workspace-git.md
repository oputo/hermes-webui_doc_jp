# ワークスペース Git コントロール

ワークスペース Git コントロールは、ブラウザがアクティブなセッションのワークスペースの Git 状態を調べられるようにします。デフォルトでは、WebUI はステータスの読み取り、ブランチ一覧、diff 表示、リモート ref のフェッチ、コミットメッセージ候補の生成ができます。リポジトリ・インデックス・worktree を変更するアクションは、WebUI プロセスを `HERMES_WEBUI_WORKSPACE_GIT_DESTRUCTIVE=1` で起動しない限り無効です。

> **信頼モデル — まずこれを読んでください。** 変更系の Git アクションを有効化すると、ブラウザのアクションがマウントされたワークスペース内で Git コマンドを実行できます。一部の Git コマンドは `.git/hooks/` や設定された `core.hooksPath` のリポジトリフックコードも実行し得ます。そのフックコードは、WebUI プロセスユーザーとして、WebUI プロセスの権限と環境で動きます。コードをダウンロードまたは実行するフックは、WebUI プロセスユーザーによるコード実行として扱ってください。

## デフォルトで動くもの

`HERMES_WEBUI_WORKSPACE_GIT_DESTRUCTIVE=1` なしで、WebUI は次ができます:

- リポジトリステータスの表示
- ブランチ一覧
- ファイル diff の表示
- 設定されたリモートからのフェッチ
- コミットメッセージ候補の生成

フェッチはリモート追跡 ref を更新し得ますが、worktree を変更したり、ブランチをマージしたり、コミットを作成したり、変更を push したりはしません。

コミットメッセージ生成は、ステージ済みまたは選択された diff コンテキストを設定済みのモデルプロバイダーへ送り得ます。UI は生成前にこれを明示します。

未追跡ファイルの diff は、WebUI がファイル内容を読む前にサイズチェックされます。大きいファイルやバイナリファイルは、インライン diff テキストの代わりにメタデータを返します。

## 明示的な有効化が必要なもの

これらのアクションは、`HERMES_WEBUI_WORKSPACE_GIT_DESTRUCTIVE=1` が設定されない限りブロックされます:

- stage / unstage
- 変更の破棄（discard）
- commit と選択ファイル commit
- pull と push
- checkout
- ローカル変更を park して復元するブランチ切り替え

WebUI がマウント済みワークスペースを調べるだけにすべきデプロイでは、フラグを未設定のままにしてください。ブラウザユーザーが WebUI からそれらのリポジトリを変更することを信頼できる場合にのみ設定してください。

フラグが有効なとき、ブランチ切り替えはローカル変更を自動的に park して復元します。離れるブランチにローカル変更があれば、WebUI はそれらの変更を WebUI 所有の Git stash に park し、ブランチを切り替え、その後入るブランチ用の WebUI 所有 stash を復元します。Git が stash をクリーンに復元できない場合、WebUI は stash をそのまま残し、それを破棄する代わりに復元失敗を報告します。

## ワークスペースとパスのスコープ

ブラウザは任意のリポジトリパスを送りません。Git リクエストはセッション ID を運び、必要に応じてワークスペース相対のファイルパスを運びます。サーバーはセッションのワークスペースを解決し、各パスをそのワークスペースに対して検査し、その後検査済みパスから Git pathspec を構築します。

Git コマンドは `shell=False` の `subprocess.run` 経由で実行されます。ローカルの status と diff コマンドは 5 秒のタイムアウトを使います。fetch、pull、push のようなリモート操作は 60 秒のタイムアウトを使います。

どの Git サブプロセスを開始する前にも、WebUI は継承された `GIT_DIR`、`GIT_WORK_TREE`、`GIT_CONFIG_GLOBAL`、`GIT_CONFIG_SYSTEM`、`GIT_CONFIG_COUNT`、`GIT_CONFIG_PARAMETERS`、および注入された `GIT_CONFIG_KEY_*` / `GIT_CONFIG_VALUE_*` の値を環境から除去します。これらの変数は Git を別のリポジトリへリダイレクトしたり config を注入したりし得るため、WebUI は親プロセスからのこれらを信頼しません。

`GIT_INDEX_FILE` は意図的な例外です。選択ファイル commit は一時インデックスを使い、WebUI が要求されたファイルのみをコミットできるようにし、その後一時インデックスを削除します。

## アクティブな run との協調

変更系の Git アクションは、同じセッションがライブストリームを持つ間は拒否されます。API は、同じワークスペースでファイルを書いているかもしれない稼働中エージェントと競合する代わりに `active_stream` を返します。

変更系の Git アクションはリポジトリごとのロックも取得します。そのリポジトリで別の Git 変更が既に動いている場合、API は `operation_in_progress` を返します。

## フックとリモートの挙動

WebUI は Git フックをバイパスしません。フックコードは `.git/hooks/` または設定された `core.hooksPath` から来得ます。

commit アクションは `pre-commit`、`commit-msg`、`post-commit` のような通常のコミットフックを実行します。push は `pre-push` を実行し得ます。pull は `--ff-only` を使うためマージコミットを作りませんが、依然 WebUI プロセス下で動く Git 操作です。

push は Git の通常の non-fast-forward 保護を保ち、non-fast-forward 拒否を一般的な Git 失敗とは別に報告します。

フックが失敗した場合、API は失敗を隠す代わりに構造化された Git エラーを返します。その他の分類済み失敗には、認証エラー、upstream ブランチの欠如、コンフリクト、dirty な worktree、無効な ref、Git バイナリの欠如、タイムアウトが含まれます。
