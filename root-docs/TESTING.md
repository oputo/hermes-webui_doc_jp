# Hermes Web UI: ブラウザテスト計画

> 本ドキュメントは、あなたまたは Claude ブラウザエージェントによる手動ブラウザテスト用です。
> 現行リリースにわたる UI のユーザー向け機能を扱います。
> 各セクションは、期待される結果付きのステップごとのテスト手順として書かれています。
> ブラウザエージェント（例: Chrome アクセスを持つ Claude）はこの計画を直接実行できます。
>
> 前提: SSH トンネルが port 8787 でアクティブ。ブラウザで http://localhost:8787 を開く。
> サーバーヘルスチェック: curl http://127.0.0.1:8787/health が {"status":"ok"} を返すべき。
>
> 自動カバレッジ: `pytest tests/ --collect-only -q` で約 7,150 テスト収集。テストは GitHub Actions により全 PR で Python 3.11、3.12、3.13（各3並列シャード）で実行され、加えて ruff lint ゲート、ヘッドレスブラウザスモークテスト、Docker スモークテストがあります。スイートは、bootstrap/静的ウィザード、実プロバイダー設定の永続化（`config.yaml` ＋ `.env`）、`/api/onboarding/*` バックエンド、オンボーディングのスキップ/既存設定ガード、思考/ツールカードアニメーションの CSS 回帰カバレッジ、ストリーミングセッションの永続化、モバイルレイアウトのブレークポイント、11 言語にわたるロケール同等性、数百の issue/PR 固定の回帰テストをカバーします。
> 実行: `pytest tests/ -v --timeout=60`
>
> ローカル回帰の焦点: 以前閉じたワークスペースパネルが、デスクトップ再読み込み時に最初の描画からブート完了まで視覚的に閉じたままであることを検証する。一瞬の開いてから閉じるフラッシュがあってはならない。

## 静的 JS ランタイム lint（brick-class 回帰ガード）

一部の JS バグは、特定の関数がブラウザで実際に実行されたときにのみ `TypeError`/`ReferenceError` を投げます — `node --check`（遅延構文チェック）、ソース存在テスト、さらにファイルの実行でさえこれらを見逃します。Issue **#3162** がまさにこれでした: `_ensureMessagesLoaded` 内で `const` バインディングが再代入され、全モバイルメッセージで「会話メッセージの読み込み」を壊しました（v0.51.161–166）。

このガードは、`static/**/*.js` に対してランタイムエラールール（`no-const-assign`、`no-import-assign`）のみを実行する、厳選された誤検知ゼロの ESLint 設定（`eslint.runtime-guard.config.mjs`）です。スタイルリンタではなく、フォーマットルールはありません。

```bash
# 一度きりの開発セットアップ（ESLint は開発専用ツール。アプリは純 Python ＋ vanilla JS のまま）:
npm install --no-save --before=<a-date-≥48h-ago> eslint   # パッケージ年齢ガード
# ガードの実行:
npm run lint:runtime
# または直接:
npx eslint --no-config-lookup -c eslint.runtime-guard.config.mjs "static/**/*.js"
```

## Python lint ゲート（ruff）— 将来志向、新コードのみ

ESLint ランタイムガードの Python 版。厳選された `ruff` ルールセット（`pyproject.toml` の `[tool.ruff]`）が潜在バグの形を捕捉します — 未使用インポート（F401）、未定義/未使用名（F841/F821）、再定義（F811）、可変デフォルト引数（B006）、raise-without-from（B904）、クロージャでのループ変数キャプチャ（B023）— **加えて** 実際の構文/ランタイムエラー（E9）。スタイル/フォーマットリンタ **ではありません**: 純スタイル系（行長、空白）は意図的にオフで、ゲートが既存コードの再フォーマットを要求することはありません。

既存ツリーは見た目のバックログ（主に未使用インポート F401）を抱えており、意図的に再フォーマット **しません**。そのためゲートは **変更が追加・修正した行のみ**（`scripts/ruff_lint.py --diff`）で強制され、バックログに触れずに新コードをクリーンに保ちます。バックログのクリーンアップは、別個の、メンテナ実行の、safe-fixes-only の判断です（#3273 で追跡）。

```bash
# 一度きりの開発セットアップ（ruff は開発専用ツール）:
pip install ruff            # または: uv tool install ruff / uvx ruff ...
# ゲート（origin/master と比較して追加/変更した行の違反のみフラグ）:
python3 scripts/ruff_lint.py --diff origin/master
# ツリー全体のバックログレポート（情報提供 — 決してブロックしない）:
python3 scripts/ruff_lint.py --all
```

`tests/test_ruff_forward_lint.py` は **ツリー全体** を E9（実構文/ランタイム）の指摘なしに保ち、厳選された設定の形を検証します。ruff がある場合スイート内で実行され、ない場合は **優雅にスキップ** します — そのため ruff のない環境はブロックされず、（ruff をインストールする）CI がそれを強制します。diff スコープのゲートは `.github/workflows/tests.yml` の `lint` ジョブとして実行され、メンテナのリリース前プリゲートの一部でもあります。

## 自動ブラウザスモーク（ランタイム brick-class ゲート）

上記の ESLint ガードは `const` 再代入 / import 代入を静的に捕捉します。**ブラウザスモーク** は同じ brick クラスを *動的に* 捕捉します — 加えて、実ブラウザがページを実行したときにのみ投げられるその他すべて（例: ESLint が見られない #2715/#2771 のような `function X(){}` / `window.X = {}` 名前衝突）。

`tests/browser_smoke.py` は実際の `server.py`（エージェントなし、一時ポート、隔離一時状態ディレクトリ）を起動し、ヘッドレス Chromium で主要ページを読み込み、読み込み時に **いずれかの** コンソールエラーや未捕捉 JS 例外が発火したら失敗します。CI（`.github/workflows/browser-smoke.yml`）で全 PR と master への push で実行され、ローカルでも:

```bash
pip install playwright && python -m playwright install chromium
python tests/browser_smoke.py
```

これは意図的に **認証情報フリー** です: サーバー起動前に環境からすべての `*_API_KEY` を剥がし、シークレットを必要とせず、実モデルを駆動しません（アプリが *クリーンに読み込み・初期化* することを検証 — 全員にとってページを壊す brick クラス）。完全なチャットゴールデンパス E2E（送信 → ストリーム → 描画 → 切り替え → 再読み込み）は、エージェント ＋ モック LLM プロバイダーを備えたメンテナのプライベート QA ハーネスにあります。

`tests/test_static_js_runtime_lint.py` は eslint がある場合これを自動実行し、ない場合は **優雅にスキップ**（明確なメッセージ）します — そのため node ツールチェーンのない環境はブロックされず、（eslint をインストールする）リリースゲートがそれを強制します。

ガードを広げるには、まず既存の意図的なヒットを修正し（2026-05-30 時点: `no-dupe-keys` ×92 i18n ロケールフォールバック、`no-func-assign` ×2 パネル上書き、`no-redeclare` ×1）、その後ルールを設定に昇格させます。

## 本ドキュメントの使い方

各テストは次を持ちます:
- SETUP: テスト前に行うこと
- STEPS: 実行する番号付きアクション
- EXPECT: 見えるべきもの（合格基準）
- FAIL: 失敗がどう見えるか

セクションを順に進めてください。各セクションは前のセクションの上に築かれます。

## Section 1: 初期読み込みと空状態

### T1.1: 新規読み込みで空状態を表示
SETUP: localStorage をクリア（DevTools > Application > Local Storage > hermes-webui-session を削除）するか、incognito で開く。
STEPS:
  1. http://localhost:8787 に移動
EXPECT:
  - ダーク背景
  - サイドバーはアイコンタブ行から直接始まる。専用ブランディングヘッダはない
  - 中央エリアに "What can I help with?" 見出しとサジェッションボタン
  - サイドバーのセッション一覧は空、または既存セッションを表示
  - サイドバーフッターに単一の "Hermes WebUI" コントロールセンターボタン
  - アクティブにハイライトされたセッションはない
  - Send ボタンは存在するが、デフォルトで入力フォーカスはない
FAIL: ページがエラー、真っ白な画面、またはユーザー操作なしに新規セッションを自動作成。

### T1.2: サジェッションボタンが動く
SETUP: T1.1 完了、アクティブセッションなし。
STEPS:
  1. "What files are in this workspace?" サジェッションボタンをクリック
EXPECT:
  - 新規セッションが自動作成される（何もなかったため）
  - "What files are in this workspace?" のテキストがユーザーメッセージとして現れる
  - ユーザーメッセージの下に thinking ドットが現れる
  - 数秒後、Hermes が応答する
FAIL: ボタンが何もしない、エラーが出る、ページがクラッシュ。

## Section 2: セッション管理

### T2.1: + ボタンで新規セッション作成
SETUP: 任意の状態。
STEPS:
  1. サイドバーの "+ New conversation" ボタンをクリック
EXPECT:
  - "Untitled" という新規セッションがセッション一覧にハイライト表示
  - 中央エリアが空状態（"What can I help with?"）を表示
  - + ボタンがセッションを作る **唯一** の方法（読み込み時の自動作成なし）
FAIL: 複数セッション作成、エラー、または空状態が表示されない。

### T2.2: メッセージ送信と応答確認
SETUP: アクティブセッションが存在。
STEPS:
  1. 下部のメッセージ入力をクリック
  2. 入力: "Say hello in exactly three words"
  3. Enter を押す（Shift+Enter ではない）
EXPECT:
  - ユーザーメッセージがチャットに即座に現れる
  - 下に thinking ドット（3 つのアニメーションドット）が現れる
  - Send ボタンが無効化（グレーアウト）
  - ターン実行中、コンポーザフッターに赤い stop ボタンが現れる
  - 10〜30 秒以内に Hermes が3語の挨拶で応答
  - thinking ドットが消える
  - Send ボタンが再有効化、stop ボタンが消える
  - サイドバーのセッションタイトルが最初のメッセージを反映して更新
FAIL: メッセージが現れない、thinking ドットが消えない、Send ボタンが永遠に無効のまま。

### T2.3: Shift+Enter で改行（送信しない）
SETUP: アクティブセッション、入力フォーカス済み。
STEPS:
  1. メッセージ入力をクリック
  2. "Line one" と入力
  3. Shift+Enter を押す
  4. "Line two" と入力
EXPECT:
  - 入力ボックスに2行のテキストが現れる
  - メッセージは送信されない（チャットにユーザーメッセージが現れない）
FAIL: Shift+Enter でメッセージ送信。

### T2.4: 再読み込みでセッション復元
SETUP: 少なくとも1往復（ユーザー ＋ アシスタント）のあるセッションが存在。
STEPS:
  1. セッションタイトルと最後のメッセージ内容を控える
  2. ページを再読み込み（Cmd+R または F5）
EXPECT:
  - 同じセッションが自動読み込み（空状態にならない）
  - 再読み込み前の全メッセージが見える
  - トップバーとサイドバーのセッションタイトルが以前と一致
FAIL: 再読み込みでセッション喪失、空状態表示、またはメッセージ欠落。

### T2.5: アクティブセッションの削除
SETUP: 少なくとも2セッション存在。1つがアクティブ。
STEPS:
  1. サイドバーのアクティブセッションにホバー（trash アイコンが現れる）
  2. アクティブセッションの trash アイコンをクリック
EXPECT:
  - "Conversation deleted" トーストが下部に約3秒現れる
  - 削除されたセッションがサイドバー一覧から消える
  - 次に新しいセッションが自動読み込み（残りがなければ空状態）
  - 新規セッションは自動作成 **されない**
FAIL: セッションが削除されない、新規セッション自動作成、エラー、または誤ったセッション読み込み。

### T2.6: 非アクティブセッションの削除
SETUP: 少なくとも2セッション存在。セッション B が非アクティブ。
STEPS:
  1. 現在アクティブ **でない** セッションにホバー
  2. その trash アイコンをクリック
EXPECT:
  - "Conversation deleted" トーストが現れる
  - そのセッションが一覧から消える
  - 現在アクティブなセッションはアクティブのまま変化なし
FAIL: アクティブセッションが変わる、複数セッション削除、またはエラー。

### T2.7: 最後のセッション削除で空状態
SETUP: ちょうど1セッション存在。
STEPS:
  1. trash アイコンでそのセッションを削除
EXPECT:
  - セッション一覧が空
  - 中央エリアが "What can I help with?" 空状態を表示
  - セッションは自動作成されない
FAIL: 新規セッション作成、エラー、または UI が壊れる。

## Section 4: ファイルアップロード

### T4.1: クリックで添付してファイルピッカーを開く
SETUP: アクティブセッション。
STEPS:
  1. コンポーザフッターのクリップアイコンをクリック
EXPECT:
  - OS のファイルピッカーダイアログが開く
  - 受け入れタイプのフィルタが見える（画像、テキスト、PDF、一般的なコードファイル）
FAIL: 何も起きない、エラー。

### T4.2: テキストファイルを添付して送信
SETUP: アップロードする小さな .txt か .py ファイルを用意。
STEPS:
  1. クリップをクリック、ファイルを選択
  2. 入力の上のコンポーザトレイにファイルチップが現れる
  3. 入力に "What is in this file?" と入力
  4. Enter を押す
EXPECT:
  - アップロード進捗バーが一瞬現れる
  - ユーザーメッセージにメッセージテキスト＋ファイル名のファイルバッジが表示
  - Hermes がファイル内容を説明または読んで応答
FAIL: アップロード失敗、ファイルバッジが現れない、Hermes がファイルに触れない。

### T4.3: ファイルをドラッグ＆ドロップ
SETUP: アクティブセッション、デスクトップにファイルを用意。
STEPS:
  1. Finder/Explorer からファイルをコンポーザエリアにドラッグ
EXPECT:
  - 青い破線ボーダーと "Drop files to upload to workspace" オーバーレイが現れる
STEPS（続き）:
  2. ファイルをドロップ
EXPECT:
  - トレイにファイルチップが現れる
  - オーバーレイが消える
FAIL: ドラッグの視覚フィードバックなし、ファイルが受け入れられない、ドロップ時エラー。

### T4.4: クリップボードからスクリーンショットを貼り付け
SETUP: スクリーンショットを撮る（Mac は Cmd+Shift+4、クリップボードに保存）。
STEPS:
  1. メッセージ入力をクリック
  2. Cmd+V（貼り付け）
EXPECT:
  - トレイに画像ファイルチップが現れる: "screenshot-{timestamp}.png"
  - ステータスバーに一瞬 "Image pasted: screenshot-..." が出る
FAIL: 何も貼り付けられない、エラー、または生のバイナリデータが入力に現れる。

### T4.5: トレイからファイルを除去
SETUP: 添付トレイに少なくとも1ファイル。
STEPS:
  1. トレイのファイルチップの X ボタンをクリック
EXPECT:
  - そのファイルがトレイから除去される
  - それが唯一のファイルなら、トレイが畳まれる
FAIL: ファイルが除去されない、エラー。

### T4.6: 可変速度付きインライン音声添付エディタ
SETUP: アクティブセッション、ローカルに音声ファイル（`.mp3`、`.wav`、`.m4a`、`.ogg`、`.flac`）を用意。
STEPS:
  1. クリップまたはドラッグ＆ドロップで音声ファイルを添付
  2. トレイに音声メディアチップが出るのを確認し、メッセージを送信
  3. 送信されたユーザーメッセージで、インライン音声プレーヤーの Play を押す
  4. 0.5×、1.25×、1.5×、2× の速度ボタンをクリック
EXPECT:
  - 音声がダウンロード/ファイルバッジだけでなくチャット内にインライン描画される
  - ネイティブ音声コントロールが見えて使える
  - クリックした速度ボタンがアクティブになり、再生速度が即座に変わる
  - 非メディアファイルのダウンロード/オープン挙動は不変
FAIL: 音声がダウンロードのみ、速度ボタンが現れない、または速度ボタンが再生に影響しない。

### T4.7: 可変速度付きインライン動画添付エディタ
SETUP: アクティブセッション、ローカルに動画ファイル（`.mp4`、`.mov`、`.webm`、`.m4v`）を用意。
STEPS:
  1. 動画ファイルを添付して送信
  2. 送信されたユーザーメッセージで、インライン動画を再生
  3. 0.75×、1×、1.5×、2× の速度コントロールを切り替え
EXPECT:
  - 動画がメッセージ幅内に収まってインライン描画される
  - ネイティブ動画コントロールが見えて使える
  - 速度選択がメディアを再読み込みせずに動画の `playbackRate` を更新

## スラッシュコマンド同等性（手動チェックリスト）

各 batch-1 コマンドについて、webui のスラッシュメニュー経由 **と** 同じ `HERMES_HOME` の `hermes` CLI 経由（該当時）の両方で実行し、同一の効果を検証する。

- [ ] `/help` — ドロップダウンが25以上のコマンドを一覧。`/help` を選ぶとそれらを列挙するアシスタントメッセージを投稿。
- [ ] `/new`（およびエイリアス `/reset`） — 新規セッションを開始。
- [ ] `/clear` — 現在のトランスクリプト表示をクリア（webui 限定の意味。CLI の「画面クリア」とは別）。
- [ ] `/title <name>` — アクティブセッションをリネーム、トップバー ＋ サイドバー更新。`/title` 単独で現在のタイトルを表示。
- [ ] `/status` — アシスタントメッセージが session_id、model、workspace、メッセージ数を表示。
- [ ] `/usage` — アシスタントメッセージがトークン数を表示。"show token usage" 設定は不変（トグルは依然 Settings パネル）。
- [ ] `/stop` — 実行中のストリームを中断。アクティブなストリームがなければ "No active task to stop." をトースト。
- [ ] `/retry` — 最後のユーザー+アシスタントの往復を除去、最後のユーザーテキストでコンポーザを再充填、再送信。最終トランスクリプトに再送信メッセージのコピーが1つだけ。
- [ ] `/undo` — 最後のユーザー+アシスタントの往復を除去。トーストで確認。空になるまで繰り返すと "Nothing to undo." をトースト。
- [ ] `/model <name>` — モデルドロップダウンを切り替え。
- [ ] `/personality` — パーソナリティを一覧。`/personality <name>` で切り替え。
- [ ] `/skills [query]` — 一致するスキルを一覧。
- [ ] `/theme <name>` — webui テーマを切り替え。
- [ ] `/workspace <name>` — ワークスペースを切り替え。

未知 / 先送り:

- [ ] `/yolo`、`/reasoning`、`/voice`、`/branch`、`/insights`、`/debug`、`/reload` など — "Web UI 暂未实现该命令: /<name>" をトースト。LLM に素のテキストとして送信 **してはならない**。
- [ ] `/compact` — "/compress is not available in the web UI yet — use the CLI for now." をトースト（このバッチ前は LLM に自由テキストを送っていた）。
- [ ] 架空のコマンド（例 `/fhfajl`） — テキストとして送信にフォールスルー（タイポ vs 実コマンドの既存挙動を保持）。

ブリッジされた CLI セッション:
